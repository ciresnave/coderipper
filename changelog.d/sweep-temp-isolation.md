**The throwaway checkout is cut off from a stray `Cargo.toml` above the temp directory, and a rule that could not run is named in the summary instead of reading as "no findings".** `cargo metadata` looks for a workspace root by walking up from the package, past the checkout into the temp directory and beyond. A stray `Cargo.toml` there (an orphan `[workspace]` whose member did not exist) made it fail in the checkout of a repository that is not itself a workspace root, so MOD-011, ERR-012, RDB-014 and OPS-011 "failed to run" on the portfolio sweep of humboldt (exit 3). The checkout's scratch directory now holds a `[workspace]` manifest naming the checkout's tracked packages, which ends the search there (tested with a decoy manifest above the temp root, for a package at the checkout root and for one below it; `exclude` does not stop the search, a `members` list that names only `wt` fails for a nested package, so the members are the tracked packages themselves); nothing is written when the checkout's own root is a workspace. The `--workspace` session checkout gets the same. Separately, the human summary now ends its "rules passed" line with the rules that could not run, by id, and the JSON summary line carries them as `rules_could_not_run` (present only when one failed); both say that a rule that failed is not a rule that found nothing. The exit code is unchanged.
