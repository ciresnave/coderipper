**WSP-011 reads a permission wall as "unverifiable with this token", not as a failure to run.** With a token that has push but not admin, the branch document shows the required checks, but `GET branches/<branch>/protection` answers 404 "Not Found" (or 403): the 0.47.18 sweep on auditant exited 3 on that alone, while the owner's token read 7 required contexts. A 403 or 404 on that call is now one Info finding saying the settings are unverifiable with this token, naming what was not checked (enforce_admins, force-push, deletion) and still judging the required-checks presence; a gateway error or any other failure stays an error, and a repository whose settings are readable is audited as before. Found by the PM, decided by this lane. Red-first tests for 404 and 403 and a control that readable settings are still audited; the mutation "404 is an error again" is caught.
