kind: Feature: a new opt-in rule
---
**COR-003 is built: a codec pair has a round-trip property test (Rust, opt-in).** The rule reads the tracked `.rs` files outside tests with `syn` and finds a *codec pair*: two public functions or methods of one scope (the same `impl` self type, or the same module; trait impl methods count as public) whose names are a verb pair, with the same optional suffix: `encode`/`decode`, `serialize`/`deserialize`, `to_bytes`/`from_bytes`, `to_json`/`from_json`, `pack`/`unpack`, `compress`/`decompress`, `encrypt`/`decrypt`, `marshal`/`unmarshal` (so `encode_header` pairs with `decode_header`, not with `decode_body`). A pair is covered when a `.rs` file of the package (test directories included) names a property-test library (`proptest`, `quickcheck`, `prop_assert`, `bolero`, `test_strategy`) and holds both function names as whole words; a pair that is not covered gets one finding at the encoder, Medium severity and Low confidence, subject `<file>:<scope>:<encoder>/<decoder>`. It is opt-in (`coderipper check COR-003`): it matches names, and it does not judge that the property asserts the round trip, nor the rule's second half (repeating normalization is stable). Fixtures `conformance/COR-003/{defective,clean}`; with the covered test inverted the conformance run fails on both twins. Measured on committed trees of eight of our repositories (2026-11-09): 17 sites in 4 repositories (12 in Unpopped, 1 in PersistAnt, 1 in synapse, 3 in auth-framework), each a real encoder and decoder pair (bit packing, `serde(with)` modules, a record codec, a TACACS header, symmetric encryption); none of the four repositories uses a property-test library at all, so the findings are the rule's claim read straight, and whether a given newtype's serde impl needs a property test is for the owner to decide, by allowlist entry with a reason.
