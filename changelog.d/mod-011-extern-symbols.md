**MOD-011 no longer reports a `-sys` crate's `pub` extern-block symbols as code nothing calls.** The reachability check read `pub` functions, statics and types declared in an `extern "C" { .. }` block as nothing, so a binding crate's whole interface looked unreferenced. The surface walk now records them (`foreign_sites`, `foreign_documented_sites`) when the block sits in a module reachable through `pub` modules, and the classifier treats them as exported (library API when documented), so a finding at one is the Info "exported" class and not Medium dead code. The API budget is unchanged (the new sets are kept apart from `public_sites`). **Output change: findings can only drop in severity or disappear; no new finding is produced.** **Measured by the coderipper lane (reported to coderipper-c by message, not re-run here) on five of our `-sys` crates (baracuda@a043b93), release builds of the prototype commit 239bbb8 (not of this PR's 99737f8) against `main`@be75c71, `--no-config` so baracuda's own `.coderipper.toml` was not applied:** Medium/Info findings old to new: kernels-sys 2844/12 to 0/2856, transformer-engine-sys 7/0 to 0/7, tensorrt-sys 2/0 to 2/0, nvshmem-sys 1/0 to 1/0, cusparse-sys 1/1 to 1/1; total Medium 2855 to 4, matching baracuda run 43854272890 (2855). **A separate finding:** the four that stay Medium (tensorrt `SUCCESS` and `FAILURE`, nvshmem `Success`, cusparse `DEFAULT`) are public constants of a `-sys` crate's API, not extern-block functions, and are deliberately not regraded. Tests: `a_pub_symbol_of_an_extern_block_is_exported_and_a_private_one_is_not`, `extern_block_symbols_are_kept_apart_from_the_budget`.
