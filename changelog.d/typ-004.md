kind: Feature: a new opt-in rule
---
**TYP-004 is built, in a narrow form: outside data becomes a domain type where it enters (Rust, opt-in).** A real check needs data-flow analysis, so this one is a syntactic approximation. It reads the tracked `.rs` files outside tests with `syn` and reports a `pub` function or inherent method (not a trait-impl method) with a parameter that is a bare string (`String`, `&str`, `&String`, `Cow<str>`, `impl AsRef<str>`, `impl Into<String>`) whose name has a domain word among its `_`-separated words (`email`, `url`, `uri`, `hostname`, `uuid`, `ip`, `phone`, `iban`, `currency`, `locale`, `timezone`, `isbn`, `postcode`, `zipcode`), unless the function's own name says it is the entry (a word `parse`, `from`, `try`, `new`, `validate`, `is`, `check`, `verify`, `normalize`, `sanitize`, `deserialize`, `decode`, `read`, `load`, `lookup`, `find`, `get`, `with`, `set`). One finding per parameter at Medium severity and Low confidence, at the function, subject `<file>:<function>:<parameter>`. The catalog marks the rule contested, and the finding is a prompt, not a proof. It is opt-in (`coderipper check TYP-004`): it does not see where data really enters, a domain type that is a `String` alias, other shapes (a bare integer id), or names outside the word list. Fixtures `conformance/TYP-004/{defective,clean}`. Not measured on a corpus, so its precision is not claimed.
