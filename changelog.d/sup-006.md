**SUP-006 is built in part: a Rust package declares a dependency that none of its source files names** (from `Cargo.toml` and the source text, name-based like `cargo-machete`). A key of `[dependencies]`, `[build-dependencies]` or `[dev-dependencies]` (and the target forms), read as the identifier code spells it (hyphen as underscore, any case), that is a token in none of the package's `.rs` files (a build dependency is read in `build.rs`) and that no `[features]` entry forwards to is reported once, at its line in `Cargo.toml`. Default on in `extended` and `portfolio`, advisory, Low severity, Low confidence. Not reported: `[package.metadata.cargo-machete] ignored` and the `cargo-udeps` ignore list (a declared exception that already exists), `-sys` and effect-only crates, a package whose source names `OUT_DIR`. Not seen: a library name that differs from the package name, a derive-only crate. Evidence: 55 Rust repos under `C:\Projects` (local checkouts, 2026-11-13): 127 findings in 16 repos (59 packages; 100 normal, 23 dev, 4 build dependencies); the first reading flagged 149, and the 22 removed by the `OUT_DIR` rule were `libc` in `bindgen`-generated `-sys` packages; of 16 findings picked at random and checked by searching the package for the name, none was used, so no false positive was found in the sample (a name that differs from its package name would not be caught by such a search). Prior art, credited: `cargo-machete` and `cargo-udeps`.
