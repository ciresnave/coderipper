kind: Breaking: three new default-on rules (SUP-005, SUP-009, OPS-009)
---
**SUP-005, SUP-009, OPS-009 (default-on) and SEC-007, REL-007 (opt-in) are built** as language-neutral checks over tracked files, each with a seeded-defect fixture and a clean twin. **SUP-005**: a package that a tracked `Cargo.lock` resolves to more than three versions is listed with its versions (Info, one finding per lockfile); the limit is chosen from the corpus (13 of 3,173 package entries in nine lockfiles) and is a constant, because settings do not reach the language-neutral module. **SUP-009**: a GitHub Actions workflow that publishes a release and names no SBOM tool (Info, at the publishing line). **OPS-009**: a Prometheus alert with no `annotations.runbook_url` (Info, at the alert's line; not applicable without a rule file that holds an alert). **SEC-007** and **REL-007** check presence only, from file names and headings (a threat model; a failure model), at Info, and are opt-in (`coderipper check SEC-007`, `REL-007`) because they fire on every repository of the corpus, this one included: the text of a document is never judged. On the nine corpus repos (committed trees, result cache off): SUP-005 reports 3 lockfiles (13 packages: `windows-sys` with 6 versions, `hashbrown`, `glam`); SUP-009 reports 1 workflow, `release.yml` of one repository (a first version also reported a `cargo publish --dry-run` line and a `docker push` to a staging registry, which is why a dry run is no longer read and `docker push` left the list); OPS-009 reports none, because no repository tracks a Prometheus rule file with an alert, so it was exercised only by its fixtures; SEC-007 and REL-007 report every repository, this one included. One reader, one pass.
