kind: Feature: a new opt-in rule
---
**OPS-002 is built, for one of its three halves: an environment variable that the code reads is documented (Rust, opt-in).** The rule reads the tracked `.rs` files outside tests with `syn` and collects each named read of the process environment: a call of `env::var("NAME")` or `env::var_os("NAME")` (`std::env` included) with a string literal, and a clap `#[arg(env = "NAME")]` (or `#[clap(..)]`). A name is reported when it looks like an environment key (upper-case letters, digits and `_`, three characters or more), is not one the platform or toolchain provides (`HOME`, `PATH`, `USER`, `USERPROFILE`, `SHELL`, `TMP`, `TEMP`, `TERM`, `LANG`, `CI`, `NO_COLOR` and the like, and any name starting `CARGO_`, `RUST_`, `XDG_`, `LC_`, `GITHUB_` or `RUNNER_`) and appears as a whole word in no tracked documentation file (`.md`, `.markdown`, `.txt`, `.rst`, `.adoc`, a file named `.env*`, `*.example` or `*.sample`, outside vendored, test, fixture and conformance directories; a `CHANGELOG` is not documentation). One finding per name at Low severity and Medium confidence, at its first read, subject the name. It is opt-in (`coderipper check OPS-002`): the record also asks that a key has a default and is used, which this does not read; a name built at run time, a read through a wrapper or a configuration crate (`config`, `figment`, `envy`), a clap builder's `.env("NAME")` and the other languages are not seen. Fixtures `conformance/OPS-002/{defective,clean}`. Not measured on a corpus, so its precision is not claimed.
