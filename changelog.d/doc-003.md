**DOC-003 is built (opt-in): each declared component carries a purpose and an owner. New optional keys `purpose` and `owner` on `[[architecture.component]]` (schema addition, additive).** Roadmap item 11 (PM ruling 2026-11-15: optional keys, absent means the rule is silent). The architecture declaration's `[[architecture.component]]` now accepts `purpose = "what it is for"` and `owner = "who answers for it"`; before this change both were rejected as unknown keys, and a declaration without them parses exactly as before. DOC-003 reads the `.coderipper.toml` at `HEAD`: a declaration in which **no** component carries either key has not adopted the convention and is "not applicable"; once any component carries one, every component without a non-blank `purpose` and a non-blank `owner` gets one Low, High-confidence finding at its `[[architecture.component]]` header, naming the missing key. Opt-in: it runs when named (`coderipper check DOC-003`), in no profile, advisory. Not judged: whether a purpose says anything, whether an owner is a real person or lane, a declaration moved to another file, purposes written only as comments. Evidence: the six repositories under `C:\Projects` with an `[architecture]` table at `HEAD` (2026-11-15) declare 133 components in all (Unpopped 9, agent-loop 22, baracuda 77, lightbulb 21, redactant 4, vulkane 0) and none carries a `purpose` or `owner` key (the two `owner` lines in lightbulb belong to `[[architecture.waiver]]` entries), so by design the rule reports nothing on them today and is silent until a project adopts the keys; its value so far is shown by 7 unit tests and a conformance pair (a component with a purpose and no owner, reported at its header line).
