kind: Fix: SEC-012 no longer reports a hand-written Debug that only says whether a secret is set
---
**SEC-012 (`no-debug-on-secrets`) read any mention of a secret field in a hand-written `Debug` as printing it.** A `Debug` that prints `<set>` or `<none>` from `self.credentials.is_some()` shows whether the secret exists and never what it is, yet it was reported (HumboldtUnifiedKidTracker `SmtpConfig`). A field used only in a presence test (`is_some`, `is_none`, `is_empty`, `is_ok`, `is_err`) is now not read; any other read that prints the value still is, and `self.token_type` no longer counts as a read of `self.token` (the whole field name is matched). **Findings only disappear for impls that print nothing of the value; rule id, severity and the derived-`Debug` case are unchanged.** The second shape of that report, a field whose type is a newtype whose hand-written `Debug` prints a hidden marker (`Passphrase(<hidden>)`), was already read as redacted since 0.47.9 (#360, nested types); a test now pins the exact humboldt shape. Evidence: three tests with the humboldt code, two of which fail when the change is reverted; a plain `Option<String>` passphrase under a derived `Debug` still fires.
