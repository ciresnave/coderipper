**RDB-002 now honours an inner `#![allow(non_snake_case)]`, `non_camel_case_types` or `non_upper_case_globals` on a file or a module, as its documentation said.** In 0.47.12 the module and file level only read `nonstandard_style`, so a file or module that allowed one naming lint still had every name of that kind reported, contradicting the rule's module documentation, its catalog `checked_today` and its changelog entry. Found by a claims audit of the rule's own documents against its code. The allow now covers its own lint (a file that allows snake case still has a lower-case type name reported) and only the scope it is written in (a module's inner allow does not reach code after the module). `nonstandard_style` still covers all three. Test: `an_inner_allow_of_a_file_or_module_covers_only_its_own_lint_and_its_scope`.
