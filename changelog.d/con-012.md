**CON-012 is built in part (Rust, opt-in): a public `async fn` whose future is not `Send`.** A new catalog record (`rules/concurrency.toml`; roadmap item 11, `docs/RULES-REVIEW-2026-11-07.md` item 4; clippy's `future_not_send` is nursery). Each Rust file is parsed with `syn`; a `pub` free `async fn`, or a `pub` `async fn` of an inherent `impl`, gets one Low finding when a parameter is typed `Rc`, is a raw pointer or is a shared `&Cell`/`&RefCell` (Medium confidence; an async fn keeps every parameter in its future), or when a local built from `Rc` or cast to a raw pointer is declared before the function's last `.await` (Low confidence). A file whose text contains `?Send`, `spawn_local`, `LocalSet` or `wasm_bindgen` is single-threaded on purpose and is not read. Opt-in: it runs when named (`coderipper check CON-012`), in no profile, advisory. Not seen: other `!Send` types (a `std` `MutexGuard`, `Ref`, `RefMut`, user types), values made by called functions, a local whose scope ends before the `.await`, `impl Future` returns, async blocks.
