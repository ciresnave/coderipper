**Every Rust rule now says so when the only Rust file it was given could not be parsed, instead of answering "the repository tracks no Rust package source".** A repository whose Rust source did not parse (a syntax error, a file `syn` cannot read) was reported by the 21 rules below as not applicable, which said that there was nothing to check when one file had not been read. The 0.47.14 batch (RDB-002, REL-002, ERR-002, TYP-004, ERR-007, OPS-002) already answered with a note that names the file; this change gives the other Rust rules the same answer through one shared helper (`rust_package::nothing_to_read`), which keeps each rule's own not-applicable sentence for the repository that really has no Rust source: CON-005, CON-010, CON-012, COR-003, COR-006, COR-007, COR-012, CON-008, REL-001, EFX-005, ERR-011, EXT-001, EXT-003, EXT-007, RDB-003, RDB-004, SEC-005, ERR-009, TST-009, TYP-005 and TYP-007. A finding is never added or removed by this: only a repository whose Rust source is entirely unparsable changes, from "not applicable" to "noted, naming the file". One table-driven test runs every rule of the registry over such a repository, lists the 52 rules that name the file, and fails if any rule answers "tracks no Rust package source", so a rule added later cannot skip it. Found by the claims audit of 2026-11-17 (the sole-unparsable-file row).
