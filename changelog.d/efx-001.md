**EFX-001 is built: a component tagged `pure = true` that names a file, network, environment, process, clock, randomness or thread API (Rust, `syn`, advisory Medium).** It reads the `[architecture]` declaration's `pure` tag (#342) and the paths the component's source names, resolved through each file's `use` declarations (a renamed import is still seen), against one effect list for the whole repository (`std::fs`, `tokio::fs`, `std::net`, `tokio::net`, `reqwest`, `hyper`, `std::env`, `std::process`, `tokio::process`, `std::time::SystemTime` and `Instant`, `chrono::Utc::now` and `Local::now`, `rand`, `getrandom`, `std::thread`, `tokio::spawn`) plus `[architecture.effects] add`, minus `remove`. One finding per site. **Nothing runs without a pure tag**: a repository with no declaration or no pure component gets "not run", never clean, unless it says `none = ["pure"]`. **`pure` means none of the listed effects is named, not referentially pure.** Also: `[architecture.effects]` entries are normalized (trimmed, trailing `::` dropped), an entry that is not a `::` path is a configuration error, and so is a `remove` entry that is not on the built-in list. Evidence: unit tests, and a seeded-defect fixture with a clean twin under `conformance/EFX-001`; no third-party repository declares a pure component yet (the 2026-11-12 reading found none with an `[architecture]` table), so there is no corpus run. See `docs/rules/efx.md`, `docs/rules/arc.md`.
