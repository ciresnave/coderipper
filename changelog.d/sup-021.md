**SUP-021 is built in part (Rust, opt-in): a build script that reaches the network, writes outside `OUT_DIR`, never says when to rerun, or uses `unsafe`.** A new catalog record (`rules/sup.toml`; roadmap item 11, `docs/RULES-REVIEW-2026-11-07.md` item 7). Every `build.rs` beside a tracked `Cargo.toml` is parsed with `syn` and gets up to four Low findings, each once at its first site: a path naming a socket or an HTTP client (`TcpStream`, `std::net`, `reqwest`, `ureq`, `curl`, `hyper` and similar); a file-system write (`fs::write`, `fs::copy`, `File::create` and similar) in a script whose text never names `OUT_DIR`; no rerun directive (the text has no `rerun` and calls no `prost_build`, `tonic_build`, `cc::` or `pkg_config`; reported at line 1); an `unsafe` block, function or impl. Opt-in: it runs when named (`coderipper check SUP-021`) and is in no profile, advisory, until a read of the portfolio's build scripts gives a denominator. Not built: proc-macro crates (the record's second half), a download through an unlisted crate or a child process, a script named by `[package] build` other than `build.rs`. Evidence: 89 repositories under `C:\Projects` (non-worktree checkouts at `HEAD`, 2026-11-14): 10 track 49 `build.rs` files in all; the rule as first written reported 14 scripts, 13 of them false (12 in baracuda call a helper `emit_rerun_hints()` that prints the directives, one in fuel/`fuel-onnx` calls `prost_build`, which prints them), so a `rerun` word and a short list of build crates (`prost_build`, `tonic_build`, `cc::`, `pkg_config`) now count as saying when to rerun; those two exclusions were fitted to those 13. After that it reports 1 script, `vulkane/build.rs`, which downloads `vk.xml` with `ureq` when it is not cached (the rule as designed, whether it is a mistake is the owner's call). No script in the 10 repositories writes outside `OUT_DIR` or uses `unsafe` by this reading; `fuel-ign1` is a second checkout of fuel and is the same script.
