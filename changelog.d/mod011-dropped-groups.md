kind: Fix: MOD-011 missed every item rustc reports in a large group
---
**MOD-011 (`reachability`) reported nothing for a dead item that rustc reports as part of a large group, and big impls will now show more findings.** When rustc finds many unused items at once it writes ONE warning ("multiple methods are never used", also "multiple associated items|associated functions|associated constants|variants|fields are never used") that names none of them and gives each its own span. The check paired names from the message with the spans, so a group with no names produced no hits: a crate with ten unused private methods in one `impl` got zero findings where rustc printed one warning. The name of each item is now read from the text rustc highlights at its span (the `text` of the span in the compiler's JSON), and an item whose span lies in macro-expanded code and cannot be named is counted in a note instead of vanishing. **Published behaviour corrected; findings only appear, none disappear.** Rule id, severity, confidence, advisory lifecycle and the grading (Info for library API, exported, test-only; Medium otherwise) are unchanged. The catalog text and the module documentation said each item the lint reports is a finding; that is now true, and says what is still not read.
**Evidence.** A seeded crate with ten unused private methods: before the fix 0 findings, now ten (test `ten_unused_methods_in_one_impl_are_ten_findings_not_silence`; the unit test `ten_unused_methods_that_rustc_groups_without_names_are_all_reported` fails with 0 hits when the fix is reverted); a real rustc JSON line for such a group is the fixture of `a_span_keeps_the_text_rustc_highlights_and_a_group_names_none_in_its_message`. On Fuel (`origin/main`): see the PR body for the finding counts before and after.
