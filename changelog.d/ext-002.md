kind: Feature: a new opt-in rule
---
**EXT-002 is built: no downcasts on abstractions (Rust, opt-in).** The rule reads the tracked `.rs` files outside tests with `syn` and reports a call that asks which concrete type is behind a value: `.downcast_ref::<T>()`, `.downcast_mut::<T>()`, `.downcast::<T>()`, `.is::<T>()`, `.type_id()` and `TypeId::of::<T>()`. A downcast to an error type (`anyhow::Error`, `Box<dyn Error>` and `io::Error` are inspected that way by design) is not reported. One finding per site at Medium severity and confidence, subject `<file>:<function>:<call>`. It is opt-in (`coderipper check EXT-002`): it reads the syntax only, so a method of another type with a downcast's name is reported too, and a registry that must know the concrete type is an allowlist entry with a reason. Fixtures `conformance/EXT-002/{defective,clean}`.
