the next planning pass starts from facts. Read at `origin/main` 81010a4 from the committed tree (`git ls-files`, `git show`), not from a working tree.

kind (212 - 28 = 184).

**How "covered" was decided.** The three sets are the rule-id constants (`crate::rule_id::X`, generated by `build.rs` from `rules/*.toml`) each route names:
the `builtin_checks!` rows, the `ID` constant of each neutral module file, the `RULE`/`SUP`/`SEC` constant of each delegate file. A second source agrees: of the
46 directories under `conformance/`, every one is in the built set (46 of 46); the two built ids with no conformance directory are `ci-protection-presence`
and `dependency-freshness` (checks that read the forge and the registry).

**Absence, with controls.** Of the 184 remaining ids, 175 appear nowhere in `src/`, `conformance/`, `tests/` or `build.rs` (`git grep` of the id as a whole
word). Control: the same query finds `RDB-008` (built) in `conformance/RDB-008/defective/expect.toml` and in `src/`. The other 9 ids do appear, all in prose, none as
a claim: `API-008` (a comment in `api_budget.rs`), `ARC-012` (`src/architecture.rs`, "not read yet"), `CON-001` (a CLI test string), `ERR-001`, `ERR-011`, `RDB-006`,

## How the table was made

A short Python script, kept out of the repository (it read the committed tree only: `git ls-files rules`, `git show HEAD:<path>`), derived the built sets above,
took each remaining rule's `title`, `domain`, `network`, `unit`, `executes_project_code`, `default_severity` and `confidence_class` from the catalog, and grouped
and sorted the rows. The "input needed", "closest check", "size" and "patent-sweep risk" cells are my judgment per rule, entered by hand into the script (a rule
is not machine-classifiable from its fields); every "closest check" path was verified to be a tracked file by the script. The ARC and MOD rows, and the top
candidates of group A, were then re-read against the lane briefs and the source.

**Columns.**

- **input needed:** `source only` (the committed tree, and for a few rules a declared configuration or an installed delegated tool); `history` (git log or diff);
  `network` (registry, forge); `a model` (the judgment of intent or meaning goes beyond syntax); `a runtime` (the rule's own text asks that tests, benchmarks,
  a race detector, a probe or a service be run: the catalog's `executes_project_code` is true for almost all of them). Where the catalog marks a rule as
  running project code but a static proxy exists, the row is `source only` and the note says "proxy" or "static half".
- **closest check to copy:** a tracked file under `src/checks` or `src/module` that does the nearest thing. The existing syntax-tree checks read Rust only
  (`syn`), so most `source only` rows are Rust unless the note says otherwise; the neutral module checks (`efx003.rs`, `rdb008.rs`) read many languages by text.
- **size:** S is one small check in an existing reader (about `ops012.rs`); M is a new reader or a configuration surface; L is new analysis machinery or several
  languages. A guess, not a measurement.
- **advisory-only:** `yes` when the catalog `default_severity` is info or low, or the `confidence_class` is low, or the family is EVO or AIH, or the row needs a
  model; otherwise `no` (medium or higher with at least medium confidence, so it could block under `--deny`). New rules still ship opt-in or Low until measured
  (lane README, step 4), whatever this column says.
- **patent-sweep risk:** `unswept, guess: ...` unless `docs/PATENT-SWEEP.md` already covers the mechanism, in which case the idea or hit number is given. Swept ideas
  that touch this list: 1, 2, 40 (reachability by compiler diagnostics: RDB-006), 19 (CON-006 lock guards: CON-002), 29 (ARC-003 declared-name counting: EFX-001),
  41 (ARC-008 single-implementation traits: EXT-007), 37 (MOD-010: TYP-003, COR-002), 12 (version gate: API-003) and hits 6 (Sonatype: AIH-002, SUP-007, SUP-012),
  42 to 51 (dependency rules: ARC-004/005 watch, DOC-004, WSP-002), 73 (Fujitsu, active: RDB-006). **A guess is not a clearance:** every `unswept` row needs
  its own sweep before a merge, per the lane README. High means the area is known to be patent-dense (history mining, clone detection, taint, flaky tests) and
  that the package-d brief's rule applies: read the sweep first.

**Cross-cutting notes.** Pairs that are one detection, to build together: CON-004 and REL-003 (bounded channels), CON-008 and REL-001 (deadlines), ERR-009 and
SEC-008 (secrets in logs), RDB-004 and TYP-007 (parameters), API-010 and DOC-002 (doc-tests), RDB-010 and DOC-006 (comments match behaviour), EFX-002 and CON-011
(global mutable state). `TYP-003` has the same text as the built MOD-010: decide whether the catalog should alias it rather than write a check. GOV-001 to GOV-009 describe CodeRipper and its
policy, not another repository; most are properties the tool either has or lacks, and are listed separately.

- **Delegated-tool overlap (OPS-006 with gitleaks, REL-005 with checkov, SUP-003 with cargo-deny)** is from the rules' text and the delegates' file names, not from running the tools.
- **GOV-001 to GOV-009:** whether CodeRipper already has each property was checked only by `grep` for words (waiver, maturity, first_party) in `src/`, not by reading the code.
- **Language coverage:** the notes name Rust forms because the existing checks read Rust; whether a rule is worth doing for other languages was not assessed.
