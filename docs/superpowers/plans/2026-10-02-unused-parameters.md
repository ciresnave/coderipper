# Unused-parameters check (project scope, Rust) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add CodeRipper's third real check: report every Rust function parameter that is never used,
in the unified `Finding` shape, with a qualified fingerprint so it can be allowlisted precisely.

**Architecture:** Rust already has this lint (`unused_variables`, default-on), so this check does not
re-detect anything. In a throwaway worktree it (1) parses each `src/**/*.rs` with `syn` to list the exact
positions of the parameters of free functions and inherent methods, (2) builds with
`cargo build --all-targets --message-format=json` and (3) keeps rustc's `unused_variables` diagnostics that land
exactly on one of those positions. No source is rewritten. A per-run sentinel (an injected function with an
unused parameter) proves the lint was live for this crate, as in the other two checks.

**Tech Stack:** Rust 2021, no new dependencies (`syn` and `proc-macro2` with `span-locations` are already
in `Cargo.toml` from the unused-return-values check).

**Spec:** `docs/superpowers/specs/2026-09-30-audit-host-design.md` §5 (`unused-parameters`, "shape (a)": for
a language whose own tooling already has the lint, surface it through the unified `Finding` schema).
**Scope, per the PM (2026-10-02): Rust only.** Shape (b) (languages with no built-in lint) and the
underscore-prefix blind spot are explicitly **not** in this plan — §5 itself says "not scoping that wrinkle in
now".

## Corrections to the spec (found by running rustc 1.98.1, not by reading)

§5 says the Rust case is "free: shell out to `cargo build`/`clippy` and translate their diagnostics". It is
mostly free, but only after three things the sketch does not mention. Reproduced on a scratch crate:

1. **rustc words an unused parameter exactly like an unused local**: both are
   reported as ``unused variable: `x` `` with code `unused_variables`. A fn with `let x = 1;` and one with `fn f(x: i32)`
   produce indistinguishable diagnostics. Translating them as-is would report every unused local as an
   unused *parameter*. **Fix:** join each diagnostic to the exact `line:column` of a parameter found by `syn`.
2. **rustc also reports parameters nobody can remove**: the forced signature of every trait-impl method,
   unused parameters in trait default bodies, and closure parameters (`.map(|e| 1)`), plus parameters of
   functions generated by a local `macro_rules!`. All reproduced; all out of scope (see Design decisions).
3. **A crate-wide `#![allow(unused_variables)]` (or `unused`) silences everything**, so a clean run is
   indistinguishable from "lint disabled". The same silent-false-clean the other two checks guard against;
   same fix (the sentinel).
   Also reproduced: an item-level `#[allow(unused_variables)]` is honoured by rustc; `mut m` is reported at the
   `mut` (not at `m`); a tuple pattern `(a, b): (i32, i32)` yields one report per unused name.

## Design decisions (rulings, with what each costs if wrong)

1. **Scope = parameters of free functions (incl. nested) and inherent-impl methods.** Excluded: trait
   declarations, trait default bodies, trait-impl methods (signature dictated by the trait), closures,
   macro-generated fns. *Cost if wrong:* a genuinely dead parameter in a trait default body is missed.
   Cheap to widen later: `sites.rs` is the only place that decides scope.
2. **An explicit item-level `#[allow(unused_variables)]` is RESPECTED; a crate-wide one makes the run error.**
   Unlike `unused-return-values` (which force-warns because it needs the lints as a *counter*), here the
   lint is the finding, and an `allow` is the user's own deliberate, visible, local decision — the allowlist
   (which requires a reason) is the sanctioned way to record such a thing for this tool. *Cost if wrong:*
   a user who `allow`s wholesale to silence rustc gets an error instead of a report; they can switch to the
   allowlist.
3. **`--cap-lints=warn` is applied**, so `#![deny(warnings)]` / `[lints]` / `-D warnings` on a lib cannot fail
   it and stop cargo compiling the bin that depends on it (the unused-return-values review found this the
   hard way; a test here pins it for this check).
4. **The fingerprint is qualified: `module::…::Type::function::parameter`** (nested fns include the enclosing
   fn). So two same-named methods in one file are distinct findings and one allowlist entry cannot hide the
   other — the limitation the allowlist milestone had to document for the other two checks.
   *Cost if wrong:* an allowlist entry breaks when a function is moved between modules.
5. **Severity `Low`, confidence `High`**: it is the compiler's own lint on a proven parameter position.
6. **`build_all_targets` takes the extra rustflags** (Task 1) and `CAP_LINTS` is shared; the
   force-warn flags move out of `cargo_json` into `unused_return_values`, which is the only caller that needs
   them. Behaviour of the existing checks is unchanged.
7. **`_`-prefixed parameters are skipped** in `sites.rs` because rustc never reports them anyway (they are the
   known blind spot, deliberately unscoped).

## Review Focus

1. **A parameter is not a local.** `fn f() { let x = 1; }` must not be reported; `fn f(x: i32) {}` must.
   → `it_reports_exactly_the_unused_parameters_of_free_functions_and_inherent_methods` (Task 3).
2. **Signatures the author cannot change must not be reported**: trait impls, trait default bodies, closures,
   macro-generated fns; and an explicit `#[allow]` is honoured. → same test (Task 3), `trait_declarations_default_bodies_trait_impls_and_closures_are_out_of_scope` (Task 2).
3. **A crate that silences or escalates the lint**: crate-wide `allow` → error, not clean; `deny(warnings)` on
   a lib must not hide the bin's parameters. → `a_crate_wide_allow_errors_instead_of_reporting_clean`, `deny_warnings_in_the_lib_does_not_hide_the_bins_parameters` (Task 3).
4. **Position fidelity**: `mut m` reported at `mut`, tuple patterns, non-ASCII text before the parameter, CRLF.
   Off by one column = silently no finding. → `a_mut_binding_is_positioned_at_mut_and_patterns_yield_every_name`, `columns_count_characters_not_bytes` (Task 2), `non_ascii_text_and_crlf_do_not_shift_the_match` (Task 3).
5. **Same-named methods on different types** must be distinct findings. → `same_named_methods_on_different_types_stay_distinct` (Task 2), `same_named_methods_on_different_types_are_distinct_findings` (Task 3).

**Known gaps accepted for v1 (documented, not tested):** the `_` blind spot; trait-method parameters;
closure parameters; functions defined inside a macro body; analysis is HEAD-only and single-package;
a parameter used only in a `#[cfg]`-disabled branch is reported (rustc says so too).

// src/checks/unused_parameters/sites.rs
//! Finds every function parameter that rustc's `unused_variables` lint could report, with the exact
//! position rustc will report it at.
//!
//! rustc words an unused parameter exactly like an unused local ("unused variable: `x`"), so the
//! diagnostic alone cannot say which one it is. Joining it to the positions found here can.
//!
//! In scope: parameters of free functions (including nested ones) and of inherent-impl methods.
//! Out of scope, on purpose: trait method declarations, trait default bodies and trait-impl methods
//! (the signature is dictated by the trait, so the parameter cannot simply be removed), closure
//! parameters, and anything inside a macro body (`syn` does not see inside one).

use syn::spanned::Spanned;
use syn::visit::Visit;

#[derive(Debug, Clone, PartialEq, Eq)]
pub struct ParamSite {
    /// Forward-slash path relative to the project root, e.g. `src/lib.rs`.
    pub file: String,
    /// 1-based line and 1-based CHARACTER column, the way rustc's JSON reports them.
    pub line: u32,
    pub column: u32,
    /// The parameter's name, e.g. `b`.
    pub name: String,
    /// Qualified function path: modules, the impl's type, enclosing functions, then the function,
    /// e.g. `m::S::method`. Qualified so two same-named functions in one file stay distinct.
    pub function: String,
}

impl ParamSite {
    /// The finding's fingerprint, e.g. `m::S::method::p`.
    pub fn subject(&self) -> String {
        format!("{}::{}", self.function, self.name)
    }
}

pub fn find_param_sites(file: &str, source: &str) -> anyhow::Result<Vec<ParamSite>> {
    let parsed = syn::parse_file(source)
        .map_err(|e| anyhow::anyhow!("could not parse {file} with syn ({e}); refusing to guess"))?;
    let mut visitor = Sites {
        file,
        scope: Vec::new(),
        out: Vec::new(),
    };
    visitor.visit_file(&parsed);
    Ok(visitor.out)
}

struct Sites<'a> {
    file: &'a str,
    scope: Vec<String>,
    out: Vec<ParamSite>,
}

impl Sites<'_> {
    fn collect(&mut self, sig: &syn::Signature) {
        let mut function = self.scope.clone();
        function.push(sig.ident.to_string());
        let function = function.join("::");
        for input in &sig.inputs {
            if let syn::FnArg::Typed(typed) = input {
                let mut idents = PatIdents(Vec::new());
                idents.visit_pat(&typed.pat);
                for (name, start) in idents.0 {
                    if name.starts_with('_') {
                        continue; // rustc exempts these by convention, so it never reports them
                    }
                    self.out.push(ParamSite {
                        file: self.file.to_string(),
                        line: start.line as u32,
                        column: start.column as u32 + 1,
                        name,
                        function: function.clone(),
                    });
                }
            }
        }
    }

    fn descend_into_body(&mut self, name: &syn::Ident, body: impl FnOnce(&mut Self)) {
        self.scope.push(name.to_string());
        body(self);
        self.scope.pop();
    }
}

impl<'ast> Visit<'ast> for Sites<'_> {
    fn visit_item_mod(&mut self, m: &'ast syn::ItemMod) {
        self.descend_into_body(&m.ident, |this| syn::visit::visit_item_mod(this, m));
    }

    fn visit_item_impl(&mut self, i: &'ast syn::ItemImpl) {
        if i.trait_.is_some() {
            return; // a trait impl's signatures are dictated by the trait
        }
        let ty = match i.self_ty.as_ref() {
            syn::Type::Path(p) => p
                .path
                .segments
                .last()
                .map_or_else(|| "<impl>".to_string(), |s| s.ident.to_string()),
            _ => "<impl>".to_string(),
        };
        self.scope.push(ty);
        syn::visit::visit_item_impl(self, i);
        self.scope.pop();
    }

    fn visit_item_trait(&mut self, _: &'ast syn::ItemTrait) {
        // declarations and default bodies: the signature belongs to the trait
    }

    fn visit_item_fn(&mut self, f: &'ast syn::ItemFn) {
        self.collect(&f.sig);
        self.descend_into_body(&f.sig.ident, |this| syn::visit::visit_item_fn(this, f));
    }

    fn visit_impl_item_fn(&mut self, f: &'ast syn::ImplItemFn) {
        self.collect(&f.sig);
        self.descend_into_body(&f.sig.ident, |this| syn::visit::visit_impl_item_fn(this, f));
    }
}

/// Every identifier bound by one parameter's pattern, with its start position. `PatIdent`'s span
/// starts at `mut` / `ref` when present, which is where rustc points.
struct PatIdents(Vec<(String, proc_macro2::LineColumn)>);

impl<'ast> Visit<'ast> for PatIdents {
    fn visit_pat_ident(&mut self, p: &'ast syn::PatIdent) {
        self.0.push((p.ident.to_string(), p.span().start()));
        syn::visit::visit_pat_ident(self, p);
    }
}

#[cfg(test)]
mod tests {
    use super::*;

    fn sites(src: &str) -> Vec<(String, String, u32, u32)> {
        find_param_sites("src/lib.rs", src)
            .unwrap()
            .into_iter()
            .map(|s| (s.subject(), s.name, s.line, s.column))
            .collect()
    }

    fn subjects(src: &str) -> Vec<String> {
        sites(src).into_iter().map(|s| s.0).collect()
    }

    #[test]
    fn a_free_function_parameter_has_its_exact_position() {
        assert_eq!(
            sites("pub fn free(a: i32, b: i32) -> i32 { a }\n"),
            vec![
                ("free::a".into(), "a".into(), 1, 13),
                ("free::b".into(), "b".into(), 1, 21),
            ]
        );
    }

    #[test]
    fn an_inherent_method_is_qualified_by_its_type_and_self_is_not_a_parameter() {
        assert_eq!(
            subjects("struct S;\nimpl S {\n    fn m(&self, p: i32) {}\n}\n"),
            vec!["S::m::p"]
        );
    }

    #[test]
    fn modules_and_enclosing_functions_qualify_the_subject() {
        let src = "mod a {\n    pub mod b {\n        pub fn f(x: i32) {\n            fn inner(y: i32) {}\n        }\n    }\n}\n";
        assert_eq!(subjects(src), vec!["a::b::f::x", "a::b::f::inner::y"]);
    }

    #[test]
    fn same_named_methods_on_different_types_stay_distinct() {
        let src =
            "struct S; struct T;\nimpl S { fn new(a: i32) {} }\nimpl T { fn new(a: i32) {} }\n";
        assert_eq!(subjects(src), vec!["S::new::a", "T::new::a"]);
    }

    #[test]
    fn a_mut_binding_is_positioned_at_mut_and_patterns_yield_every_name() {
        assert_eq!(
            sites("fn f(mut m: i32, (a, b): (i32, i32)) {}\n"),
            vec![
                ("f::m".into(), "m".into(), 1, 6),
                ("f::a".into(), "a".into(), 1, 19),
                ("f::b".into(), "b".into(), 1, 22),
            ]
        );
    }

    #[test]
    fn underscore_prefixed_names_are_skipped_because_rustc_never_reports_them() {
        assert_eq!(subjects("fn f(_a: i32, b: i32, _: i32) {}\n"), vec!["f::b"]);
    }

    #[test]
    fn trait_declarations_default_bodies_trait_impls_and_closures_are_out_of_scope() {
        let src = "\
trait T {
    fn req(&self, r: i32);
    fn dflt(&self, d: i32) {}
}
struct S;
impl T for S {
    fn req(&self, r: i32) {}
}
fn uses_closure() { let _ = |e: i32| 1; }
";
        assert_eq!(subjects(src), Vec::<String>::new());
    }

    #[test]
    fn columns_count_characters_not_bytes() {
        // `é` is 2 bytes; rustc reports a 1-based character column.
        let found = sites("/* é */ fn f(a: i32) {}\n");
        assert_eq!(found, vec![("f::a".into(), "a".into(), 1, 14)]);
    }

    #[test]
    fn a_file_syn_cannot_parse_is_an_error_not_a_silent_skip() {
        assert!(find_param_sites("src/lib.rs", "this is not rust {{{").is_err());
    }
}

// src/checks/unused_parameters/sentinel.rs
use std::path::Path;

/// Neither name starts with `_`: rustc exempts underscore-prefixed names from `unused_variables`,
/// which would silence the very lint the sentinel exists to prove is live.
pub const SENTINEL_FN: &str = "coderipper_unused_param_sentinel_7d41";
pub const SENTINEL_ARG: &str = "coderipper_unused_param_arg_7d41";

/// Appends a function with one unused parameter to `src/lib.rs` (preferred) or `src/main.rs`. If
/// this run's build does not report that parameter, `unused_variables` is suppressed crate-wide and
/// no result can be trusted. Returns the file it wrote to.
pub fn inject_sentinel(worktree_root: &Path) -> anyhow::Result<String> {
    for candidate in ["lib.rs", "main.rs"] {
        let path = worktree_root.join("src").join(candidate);
        if path.exists() {
            let mut content = std::fs::read_to_string(&path)?;
            content.push_str(&format!(
                "\n#[allow(dead_code)]\nfn {SENTINEL_FN}({SENTINEL_ARG}: i32) {{}}\n"
            ));
            std::fs::write(&path, content)?;
            return Ok(format!("src/{candidate}"));
        }
    }
    anyhow::bail!("neither src/lib.rs nor src/main.rs exists under {worktree_root:?}")
}

// src/checks/unused_parameters/mod.rs
//! Unused-parameters check (project scope, Rust): which function parameters are never used?
//!
//! Rust already has this lint (`unused_variables`), default-on. What it does not do is report in
//! CodeRipper's unified `Finding` shape, ignore the forced signatures of trait impls, or tell a
//! parameter from a local (rustc words both identically). So this check does not re-detect
//! anything: it builds the crate in a throwaway worktree, takes rustc's own `unused_variables`
//! diagnostics, and keeps those that land exactly on a parameter of a free function or inherent
//! method, as found by `syn` (see `sites`).
//!
//! **Known limitations / deliberate scope (design doc §5):**
//! - `_`-prefixed parameters are exempt by Rust convention and never reported. The spec notes the
//!   blind spot ("accepted and silently ignored") and explicitly does NOT scope it in.
//! - Trait declarations, trait default bodies, trait-impl methods and closure parameters are out of
//!   scope (see `sites`); so is anything defined inside a macro body.
//! - An explicit `#[allow(unused_variables)]` on an item is respected: it is a deliberate, visible,
//!   local decision (use the allowlist to record a reason). A CRATE-wide allow, which would silence
//!   every parameter, makes the sentinel fail and the run errors instead of reporting clean.
//! - Analysis is HEAD-only, single-package projects only, as with the other checks.

mod sentinel;
mod sites;

use crate::cargo_json::{build_all_targets, Diagnostic, CAP_LINTS};
use crate::check::{Check, CheckContext, Network, Scope};
use crate::finding::{Confidence, Finding, Location, Severity};
use crate::worktree::RewrittenWorktree;
use sentinel::{inject_sentinel, SENTINEL_ARG, SENTINEL_FN};
use sites::{find_param_sites, ParamSite};
use std::collections::BTreeSet;

pub const CHECK_ID: &str = "unused-parameters";

pub struct UnusedParametersCheck;

impl Check for UnusedParametersCheck {
    fn id(&self) -> &'static str {
        CHECK_ID
    }

    fn scope(&self) -> Scope {
        Scope::Project
    }

    fn network(&self) -> Network {
        Network::LocalOnly
    }

    fn run(&self, ctx: &CheckContext) -> anyhow::Result<Vec<Finding>> {
        let mut sites: Vec<ParamSite> = Vec::new();
        // The rewrite is the identity: this check reads the source, it does not change it.
        let wt = RewrittenWorktree::create_with(&ctx.project_root, |file, source| {
            sites.extend(find_param_sites(file, source)?);
            Ok(source.to_string())
        })?;
        let sentinel_file = inject_sentinel(&wt.root)?;
        // `--cap-lints=warn`: a `#![deny(warnings)]` must not fail the build and hide the lint.
        let build = build_all_targets(&wt.root, CAP_LINTS)?;

        anyhow::ensure!(
            !build.is_broken(),
            "this crate's build reported real compiler error(s) (or failed without any diagnostic), \
             so no result can be trusted"
        );

        let hits = unused_variable_hits(&build.diagnostics);
        anyhow::ensure!(
            hits.iter().any(|h| h.name == SENTINEL_ARG),
            "unused-parameters' own per-run positive control (an unused parameter injected into \
             {sentinel_file}) was not reported by rustc even though the build reported no errors -- \
             `unused_variables` is suppressed crate-wide in this crate (e.g. #![allow(unused)] or \
             #![allow(unused_variables)]), so this run's result can't be trusted."
        );

        let project = ctx
            .project_root
            .file_name()
            .map(|n| n.to_string_lossy().to_string())
            .unwrap_or_default();
        let positive_control = format!(
            "this run's own sentinel (parameter `{SENTINEL_ARG}` of `{SENTINEL_FN}`, injected into \
             `{sentinel_file}`) WAS reported by rustc's `unused_variables`, so the lint was live for \
             this crate in this same build"
        );

        let mut findings: Vec<Finding> = sites
            .iter()
            .filter(|site| {
                hits.iter()
                    .any(|h| h.file == site.file && h.line == site.line && h.column == site.column)
            })
            .map(|site| Finding {
                check_id: CHECK_ID.into(),
                severity: Severity::Low,
                confidence: Confidence::High,
                project: project.clone(),
                location: Some(Location {
                    file: site.file.clone(),
                    line: Some(site.line),
                }),
                subject: Some(site.subject()),
                summary: format!(
                    "parameter `{}` of `{}` is never used",
                    site.name, site.function
                ),
                detail: format!(
                    "Reported by rustc's own `unused_variables` lint and kept because it lands on a \
                     parameter of a free function or inherent method (not a local, closure or trait \
                     signature). Defined at {}:{}. Prefixing the name with `_` silences rustc, which \
                     this check does not look for.",
                    site.file, site.line
                ),
                positive_control: Some(positive_control.clone()),
            })
            .collect();
        findings.sort_by(|a, b| {
            let key = |f: &Finding| {
                f.location
                    .as_ref()
                    .map(|l| (l.file.clone(), l.line))
                    .unwrap_or_default()
            };
            key(a).cmp(&key(b))
        });
        Ok(findings)
    }
}

/// One `unused_variables` report, de-duplicated (`--all-targets` compiles shared code twice).
#[derive(Debug, PartialEq, Eq, PartialOrd, Ord)]
struct Hit {
    file: String,
    line: u32,
    column: u32,
    name: String,
}

fn unused_variable_hits(diagnostics: &[Diagnostic]) -> BTreeSet<Hit> {
    diagnostics
        .iter()
        .filter(|d| d.code.as_deref() == Some("unused_variables"))
        .filter_map(|d| {
            let span = d.primary_span()?;
            // "unused variable: `b`" -> b
            let name = d.message.split('`').nth(1)?.to_string();
            Some(Hit {
                file: span.file.clone(),
                line: span.line,
                column: span.column,
                name,
            })
        })
        .collect()
}
