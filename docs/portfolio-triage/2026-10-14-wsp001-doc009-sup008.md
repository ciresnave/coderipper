# Portfolio triage: WSP-001, DOC-009, SUP-008 (the three rules that gate "all rules by default")

**Report only.** No repository other than this one was changed. Produced 2026-10-14 by the CodeRipper lane at the PM's task (ROADMAP item 3); it supersedes the 2026-10-13 sweep numbers (WSP-001 23, DOC-009 21, SUP-008 21 of 26) because the population and the commit of each repository differ, as the table below shows.

## What was measured

- **Tool:** `coderipper` 0.6.23 built from `main@7799276`; `coderipper --no-config check <RULE> --profile extended --deny none --message-format json --project <clone>`, once per rule per repository (81 runs). zizmor 1.30.1 for SUP-008. No repository's `.coderipper.toml` waives anything (`waived` is 0 in all 81 runs; only this repository has the file).
- **Subject:** a depth-1 clone of each repository's default branch from its remote on 2026-10-14 (every default branch is `main`), so it is the forge's `origin/main`, never a working tree. Enumeration is `git ls-files` inside the clone (the rules' own).
- **Population:** 27 repositories = every directory under `C:\Projects` with a `.git` directory (not a worktree file) and an `origin`, minus `cutlass` (a third-party NVIDIA checkout) and the two `auth-framework-ghsa-*` private advisory forks (scratch). `claude-code-wrapper` and `llm-bench` have no `origin` and are not in it. 18 are under `ciresnave/`, 8 under `ThinkersJournal/`, 1 under `EvansLaboratories/`. The 2026-10-13 sweep had 26; this list has one more (the difference is not recorded, so I cannot say which).
- **Positive control:** the rules' own counts include repositories that are clean, so the query is not an always-fire: WSP-001 is clean on 3 (each tracks `.github/CODEOWNERS` with `* @ciresnave`), DOC-009 on 1 (`coderipper` keeps a glossary), SUP-008 on 9 (no finding; the same zizmor run finds 326 on the other 18).

## DOC-009: a repository that documents itself keeps a glossary

All 21 findings are **Info severity, low confidence** (the rule's own grading) and the same finding: tracked `.md` under `docs/` and no file whose name contains `glossary`. No repository has a glossary with a duplicated term.

Doc-page counts below are the rule's own positive-control figure (tracked `.md` files under `docs/` or `doc/`). **The split at 10 pages is my heuristic, not a rule**: the rule fires on a single page, and a glossary for one to six pages is mostly ceremony.

|---|---|---|
| **True defect** (12) | `fuel` (293), `baracuda` (90), `synapse` (80), `ThinkersJournal-Community` (77), `auth-framework` (72), `lightbulb` (59), `HumboldtUnifiedKidTracker` (33), `KISS` (22), `agentlife` (18), `mlmf` (17), `Unpopped` (15), `amt` (11) | Add `GLOSSARY.md` (or `docs/glossary.md`) defining the project's domain terms once each. | **Rule too strict** (9) | `auto-discovery` (6), `ThinkersJournal.com` (4), `unisql` (4), `kiss-ref` (3), `SafeImage` (3), `consent` (2), `OverMind` (2), `PersistAnt` (1), `ThinkersFoundation` (1) | A threshold in the rule (for example "at least 10 pages") removes all nine with no per-repository waiver; the alternative is nine waivers saying "N pages; terms live in the README".
